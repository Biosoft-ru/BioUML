- 2026-09-10 — Phase 5 done: HTTP/SSE endpoint + in-process server + auth. Architecture: a self-contained `McpJsonRpcDispatcher` (protocol 2025-03-26) is the shared protocol core for BOTH the HTTP servlet and the in-process server, guaranteeing identical tool lists + error shape. `McpServlet` (plain `javax.servlet HttpServlet`, mapped at `/mcp` in `bioumlweb.war`) exposes a transport-agnostic `handle(method,path,query,headers,body)→HandleResult{status,body}`; the `doPost` wrapper only reads the body, folds the JSESSIONID cookie into the query, and writes the result. Auth reuses BioUML web session: the **system** session is privileged (it carries no user record by design — `getSessionUser()` returns null for it), any other session must have a logged-in user or the request → 401 with a structured JSON-RPC error. Key learnings: (a) the build's `javax.servlet` API differs between Maven (newer) and Ant (older, no `HttpServletResponse.setCharacterEncoding`) — don't call version-specific methods; put `charset=UTF-8` in the Content-Type header instead. (b) Implementing `HttpServletRequest`/`HttpServletResponse`/`HttpSession` stubs in tests is version-fragile (HttpSession needs `removeValue`, `ServletContext` symbol missing, etc.) — drive the transport-agnostic `handle()` core directly instead. (c) `SecurityManager.anonymousLogin()` is a NO-OP for `SYSTEM_SESSION` (guarded by `if (!sessionId.equals(SYSTEM_SESSION))`), so the system session never gets a user record — the "authenticated" test session must be the system session, and the servlet must treat the system session as privileged. (d) Real-socket HTTP test: read the header region verbatim up to the first blank line + exactly `Content-Length` body bytes (NOT to EOF) — reading to EOF hangs on HTTP/1.1 keep-alive. 46/46 Mcp*Test; both builds green; McpServlet.class in bioumlweb.war + /mcp mapping verified.

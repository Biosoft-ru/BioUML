# Guides for the analyses of the BioUML platform, written for agents that help a user who is not a
# bioinformatician. Format: see McpGuides. One entry per analysis; "||" lists analyses that share an entry.
# Keep to what the analysis does: parameter names are those biouml_analysis_describe returns.

# ============================================================================ research topics

== topic: basics | How work is done here: data, identifiers, running, reading results
summary: Read first. Projects, tables and tracks, identifier types, how to pass parameters, how to run and poll, how to report results to the user.
Data lives in a repository of paths. A user's own data and results belong in a project: data/Projects/<project>/Data/... (biouml_project lists and creates projects). Reference data is under databases/ (genomes, gene annotation, pathway and motif databases) and data/Public or data/Examples (shared example data). Never write outside the user's project.

The two data kinds almost everything works on:
- Table: rows with an id and columns. The id column has a type (reference type), e.g. 'Genes: Ensembl', 'Genes: Gene symbol', 'Proteins: UniProt', 'Probes: Affymetrix'. A "gene set" or "gene list" is simply a table whose row ids are genes; numeric columns (fold change, p-value, expression) are optional.
- Track: genomic intervals (sites) on a genome: ChIP-seq peaks, variants (VCF), promoters, predicted binding sites. A track is bound to a genome build (hg19, hg38, mm10, ...): biouml_bsa_track_genome tells which. Never mix builds.

Identifiers matter more than anything else. Most gene-level analyses (functional classification, enrichment, promoter analysis, regulator search) expect Ensembl gene ids as row ids. If the user's table has gene symbols, probe ids, UniProt, Entrez or anything else, run 'Convert table' first (targetType 'Genes: Ensembl'), and tell the user how many rows could not be converted (its unmatchedTable). Workflows usually do this conversion themselves.

Getting data in: biouml_repo_import for a file on the server; the analysis 'Upload from FTP' for a URL (ftp, http(s), Google Drive share link). A small gene list can be made directly: biouml_repo_new_element kind 'table', then biouml_table_add_row or biouml_table_replace. After importing a table check with biouml_analysis_get_result that the id column and the numeric columns look right.

Choosing what to run: biouml_analysis_guide (topics) -> biouml_analysis_list (query) -> biouml_analysis_describe (guide, parameters) -> biouml_analysis_run -> biouml_task op status until done -> biouml_analysis_get_result on the outputs.

Parameters:
- Paths are plain strings. An output path must be new: name it after what it holds, in the folder of the input (e.g. '<input> GO enrichment').
- A parameter that chooses a column ('columnName', 'weightColumn', ...) lists its choices only after the table is known: call biouml_analysis_describe with params {<table parameter>: <path>} and read allowedValues.
- A group of columns of one table is a nested value: 'experimentData/tablePath': <table>, 'experimentData/columns': [<column names>].
- A choice parameter must be given exactly as one of its allowedValues (e.g. species 'Human (Homo sapiens)'). Long lists (diseases, tissues) are searched with the filter argument of biouml_analysis_describe.
- Leave expert parameters at their defaults unless the user asks; say which defaults were used when they shape the result (cutoffs, species, genome build, background set).

Reading and reporting results: read tables page by page with biouml_analysis_get_result (columns to keep it small). Report the top rows with their statistics, say what the numbers mean in plain words, and state the caveats (number of input genes actually used, multiple-testing correction, predictions versus measurements). Give the repository path of every result so the user can open it in the web UI. A statistically significant list is a hypothesis, not a proof: say so.

== topic: tables | Working with tables: filter, join, annotate, convert identifiers, plot
summary: Which table analysis does what: subsets, joins, annotation, identifier conversion, transformations and plots.
- Look at a table: biouml_analysis_get_result (column names, types, rows).
- Convert identifiers: 'Convert table' (same species), 'Convert table via homology' (to another species via orthologs).
- Add gene symbols, descriptions and other annotation columns: 'Annotate table' (annotationCollectionPath e.g. databases/EnsemblHuman104/Data/gene with annotationColumns such as title and description).
- Keep some rows: 'Filter table' (a JavaScript condition on column names, or the N rows with the highest or lowest value of a column), 'Select top rows', 'Select random rows', 'Filter duplicate rows'.
- Keep some columns: 'Select table columns'. New column from a formula: 'Add calculated column'. Log or power transform: 'Transform table'.
- Combine tables by row id: 'Join two tables' (inner, outer, left, right join; choose columns), 'Join several tables' (more than two), 'Venn diagrams' (how up to three lists overlap, with the overlap tables).
- Statistics and plots on a table: see topic expression-table for differential expression; 'Volcano plot', 'MA plot', 'Heatmap', 'PCA', 'Plot bar chart', 'Plot pie chart', 'Dot plot' for pictures.
- Table to genomic intervals and back: 'Convert table to track', 'Convert track to table', 'Gene set to track' (promoters or gene regions of a gene list), 'Track to gene set' (genes near the sites of a track).
Every analysis writes a new table and leaves its input unchanged.

== topic: tracks | Working with genomic tracks: peaks, intervals, variants
summary: Which track analysis does what: filter, intersect, merge, resize, annotate with genes, convert to gene lists.
- Which genome is it on: biouml_bsa_track_genome. Sites of a track are read like table rows with biouml_analysis_get_result.
- Genes near sites: 'Track to gene set' (a gene table with site counts) or 'Annotate track with genes' (gene names written into each site).
- Promoters or gene bodies of a gene list as a track: 'Gene set to track' (from/to relative to the transcription start site, e.g. -1000..100).
- Keep or remove the sites that overlap another track: 'Filter one track by another' (mode Intersect or Subtract). Filter by a condition on position or site properties: 'Filter track by condition'.
- Resize sites (e.g. +-50 bp around peak summits), merge overlapping ones, drop short ones: 'Process track with sites'. Remove overlaps keeping the best site: 'Remove overlapping sites'. Merge nearby sites into clusters: 'Cluster track'. Combine several tracks: 'Join tracks'. Drop exact duplicates: 'Reduce track'.
- Variants: 'Filter VCF by genotype' (the variant calls of each sample), 'Mutation effect' (effect on proteins), 'Mutation effect on sites' (transcription factor binding sites gained or lost), 'SNP matching' (rs ids to positions and genes).
- Transcription factor binding sites in the sequences under a track: 'Site search on track'.

== topic: simulation | Mathematical models: build, simulate, flux balance
summary: Simulating a diagram's model (SBML and others) and flux balance analysis of metabolic models.
A model is a diagram with species, reactions, equations and events. Import one (SBML, CellML, SED-ML, BioUML dml: biouml_repo_import or biouml_diagram_import) or build it with the biouml_diagram_* tools; biouml_diagram_describe shows its variables. Simulate it with biouml_simulation_start (solver list: biouml_simulation_list_solvers), poll biouml_simulation_status, then read or plot with biouml_simulation_output. 'Simulation analysis' does the same as an analysis and saves the result in the repository, which is what a workflow or a repeatable record needs.
Flux balance analysis of a metabolic network: 'Building Flux Balance DataTable' (or 'Score based FBC table builder' to derive the bounds from expression data) makes the table of bounds and objective coefficients, 'Flux Balance Constraint' computes the optimal fluxes.

# ============================================================================ import

== analysis: Upload from FTP
summary: Fetch a file from a URL (ftp, http(s), Google Drive share link) into the repository and import it in a chosen format.
use: The user's data is on the internet or in cloud storage rather than on the server. The usual first step of any work with the user's own data.
input: fileURL; resultPath (a new element in the user's project, e.g. data/Projects/<project>/Data/<name>); importerFormat, one of its allowedValues, e.g. 'Tabular (*.txt, *.xls, *.tab, etc.)', 'VCF format (*.vcf)', 'BED format (*.bed)'.
output: the imported table, track, sequence or file at resultPath.
next: check the result with biouml_analysis_get_result; for a track check its genome with biouml_bsa_track_genome.
tips: Pick the format that matches the file, not 'Generic file', or the data stays an unparsed file. A file on the server itself is imported with biouml_repo_import instead.

== analysis: Tabular (*.txt, *.xls, *.tab, etc.)
summary: Import format for tables: tab- or comma-separated text and Excel sheets become a table with typed row ids.
use: Any spreadsheet-like data: gene lists, expression matrices, statistics tables. Use it through biouml_repo_import or as importerFormat of 'Upload from FTP'; it is not run by itself.
input: the file; properties/columnForID (the column holding the row ids, e.g. gene ids), properties/tableType (the id type, e.g. 'Genes: Ensembl'; '(auto)' detects it), properties/headerRow and properties/dataRow (1-based line numbers), properties/delimiterType.
output: a table.
tips: Row ids must be unique: with repeated ids set properties/addSuffix or properties/generateUniqueID. If the id type stays 'Unspecified', gene analyses will not recognise the rows: set tableType or run 'Convert table' with the right sourceType.

== analysis: BED format (*.bed) || General Feature Format (*.gff) || Wiggle format (*.wig)
summary: Import formats for genomic intervals (BED, GFF) and signal (WIG): the file becomes a track bound to a genome.
use: ChIP-seq/ATAC-seq peaks, regions of interest, annotation. Used through biouml_repo_import or 'Upload from FTP'.
input: the file; properties/dbSelector, the genome the coordinates refer to (one of its allowedValues, e.g. an Ensembl human hg38 entry) — or properties/genomeId such as 'hg19'.
output: a track.
tips: The genome build must be the one the file was made with: ask the user when it is not stated. A track without a genome cannot be used for sequence analyses (site search).

== analysis: Fasta format (*.fasta) || EMBL format (*.embl) || GenBank format (*.gb)
summary: Import formats for DNA sequences (FASTA, EMBL, GenBank): the file becomes a sequence collection.
use: The user has their own sequences (a plasmid, a cloned promoter, a non-model genome) rather than coordinates on a reference genome.
output: a sequence collection; it can be searched for binding sites with 'Site search on track' or the 'Analyze any DNA sequence' workflows.

== analysis: ZIP-archive (*.zip)
summary: Import format for an archive of files of one format: each file is imported into a folder.
use: Many files at once, e.g. the CEL files of a microarray experiment or a set of gene lists.
input: properties/importerInfo, the format of the files inside (autodetection does not work here: set it).
output: a folder with the imported elements.

== analysis: Generic file
summary: Import format that stores a file as it is, without parsing it.
use: Only for files that analyses read as files (FASTQ, BAM, archives, documents). A table or track imported this way cannot be analysed: use its own format.

== analysis: SBML || SBML(CellDesigner) || CellML || BioUML format(*.dml) || SED-ML file || SIF
summary: Import formats for models and networks: SBML, CellDesigner SBML, CellML and BioUML diagrams, SED-ML simulation experiments, SIF interaction lists.
use: Bringing an existing mathematical model or interaction network into the repository as a diagram. See topic simulation.
output: a diagram (SED-ML: the simulation experiment with its models).
next: biouml_diagram_describe, then simulate or edit.

== analysis: SDF file
summary: Import format for chemical structures (SDF): a collection of compounds with their data fields.

== analysis: Text output file generated by R (.Routput)
summary: Internal import format for the text output of R scripts; not for user data.

# ============================================================================ tables

== analysis: Convert table
summary: Convert the row identifiers of a table to another type (gene symbols, probes, UniProt, ... to Ensembl genes and back), merging rows as needed.
use: Before almost every gene-level analysis: they expect 'Genes: Ensembl' row ids. Also to get proteins, transcripts, pathway-database molecules or gene symbols from a gene table.
input: sourceTable; species; sourceType ('(auto)' usually detects it); targetType (its allowedValues appear after sourceTable and species are bound: describe with params). idsColumnName when the identifiers are in a column rather than the row ids.
output: outputTable with the new ids, and unmatchedTable with the rows that could not be converted.
next: any gene-list analysis ('Functional classification', 'Enrichment analysis', promoter and network analyses).
tips: Several source ids can map to one target id: numeric columns are then merged by aggregator (extreme, average, ...) on columnName. Report how many rows were lost. For another species' orthologs use 'Convert table via homology'.

== analysis: Convert table via homology
summary: Map the genes of a table to their orthologs in another species (Ensembl Compara).
use: The data is from one organism (e.g. mouse, rat) and the analysis or database is for another (usually human).
input: sourceTable, species (source), targetSpecies, targetType.
output: outputTable in the target species, unmatchedTable.
tips: Genes without an ortholog are lost and one-to-many orthologs multiply rows: report the counts.

== analysis: Annotate table
summary: Add annotation columns (gene symbol, description, chromosome, ...) from a database or another table to the rows of a table.
use: Making a result readable for a person: a table of Ensembl ids gets gene symbols and descriptions. Also to copy columns from another table by row id.
input: inputTablePath; annotationCollectionPath (e.g. databases/EnsemblHuman104/Data/gene for human genes, or any table); annotationColumns (allowedValues appear once the source is bound; for genes 'title' is the symbol and 'description' the name).
output: outputTablePath: the input with the new columns.

== analysis: Super annotate table
summary: Annotate a table with columns from several other tables at once.
use: Like 'Annotate table' with more than one annotation source.

== analysis: Filter table
summary: Keep the rows of a table that satisfy a condition, or the N rows with the highest or lowest values of a column.
use: Selecting significant genes from a statistics table (e.g. adjusted p-value below 0.05 and absolute log fold change above 1) to get the gene set for downstream analyses.
input: inputPath; filterExpression, a JavaScript condition on column names, e.g. 'adj_P_Val < 0.05 && Math.abs(logFC) > 1' (characters that are not letters, digits or _ in a column name are written as _); filteringMode and valuesCount for the top-N modes.
output: outputPath, a new table.
tips: Read the column names first (biouml_analysis_get_result). Tell the user how many rows passed; an empty result usually means a wrong column name or a cutoff that is too strict.

== analysis: Fast table filter
summary: Filter a large table with an SQL-like condition.
use: Like 'Filter table' for tables too large to filter row by row; the condition is SQL ('ColumnA > 5 AND ColumnB < 0.05').

== analysis: Select top rows
summary: Take the top, middle or bottom rows of a table ordered by a column, by count or percent.
use: The N most up- and down-regulated genes, or the strongest hits of any ranking.
input: inputTable, column, types (Top, Middle, Bottom) with topCount/topPercent and the output for each.

== analysis: Select random rows
summary: Take a random sample of the rows of a table.
use: A random background set, or a smaller table for a quick trial.

== analysis: Select table columns
summary: Make a table with only the chosen columns.
input: columnGroup/tablePath and columnGroup/columns.

== analysis: Filter duplicate rows
summary: Remove rows that repeat a value in a column, keeping one of them (optionally the one with the best score).

== analysis: Group table rows
summary: Merge rows that have the same value in a column into one row.

== analysis: Add calculated column
summary: Add a column computed from other columns by a JavaScript expression.
use: A derived value: a ratio, a log, a flag ('logFC > 0 ? "up" : "down"').
input: inputPath, newName, type (e.g. Float, Text), expression using column names as variables.

== analysis: Transform table
summary: Apply log2, log10, power or exp to chosen columns of a table.
use: Raw intensities need a log scale before statistics; or going back from log values.

== analysis: Merge table columns
summary: Merge several columns of a table into one (average, extreme, ...).

== analysis: Table imputation
summary: Replace missing values of a table with row means.
use: Before statistics or clustering that cannot handle missing values.

== analysis: Quantile normalization
summary: Make the value distributions of all columns of a table identical (quantile normalization).
use: Making samples comparable when they were not normalized together.

== analysis: Replace outliers
summary: Clip the values of chosen columns to a lower and an upper bound.

== analysis: Join two tables || Join full tables || Join tables
summary: Join two tables by row id into one, with chosen columns from each (inner, outer, left or right join).
use: Putting results side by side: fold changes from two comparisons, expression next to enrichment hits.
input: leftGroup/tablePath, leftGroup/columns, rightGroup/tablePath, rightGroup/columns, joinType.
output: output, a table. Both tables must use the same id type.

== analysis: Join several tables
summary: Intersect or join more than two tables by row id, keeping all columns.

== analysis: Intersect tables
summary: The rows whose ids are in both tables.
use: The genes common to two lists. For the overlap picture and all subsets use 'Venn diagrams'.

== analysis: Venn diagrams
summary: Draw how two or three lists overlap and save every overlap and difference as a table.
use: Comparing gene lists: which genes are shared between conditions, which are unique.
input: table1Path, table2Path, table3Path (optional); the tables must use the same id type.
output: a folder with the picture and the subset tables.

== analysis: Create folder
summary: Create a folder in the repository.

== analysis: Check quotas
summary: Administrative: check the disk space used by projects.
use: Not a research tool.

== analysis: Convert .hic to table
summary: Convert a Hi-C contact file (.hic) to a table at a given resolution.

# ============================================================================ plots

== analysis: Volcano plot
summary: Volcano plot of a differential expression table: fold change against significance, with the top genes labelled.
use: The standard picture of a differential expression result.
input: inputTable, logfcColumn, pvalueColumn, labelsColumn (gene symbols), cutoffs.
output: outputChart, an image.

== analysis: MA plot
summary: MA plot of a differential expression table: fold change against mean expression.

== analysis: Plot bar chart || Plot pie chart
summary: Bar or pie chart of one numeric column of a table, labelled by another column.

== analysis: Dot plot
summary: Dot plot of an enrichment result: categories with dot size by number of genes and position by significance.
use: A picture of the top categories of 'Functional classification' or 'Enrichment analysis'.

== analysis: TreeMap on Functional classification
summary: Treemap picture of a GO functional classification result, grouping similar GO terms.
use: A long GO result is easier to grasp as clusters of related terms.
input: sourcePath, the result of 'Functional classification' with a GO classification; pvalueColumn.

# ============================================================================ expression statistics

== analysis: Up and Down Identification
summary: Find up- and down-regulated genes between an experiment and a control group of columns (Student's t-test or Wilcoxon).
use: A simple two-group comparison on a normalized expression table when each group has several replicates. For RNA-seq counts or designs with more factors prefer the linear-model tools when they are available.
input: experimentData/tablePath + experimentData/columns, controlData/tablePath + controlData/columns (both groups may be columns of the same table); method; inputLogarithmBase; outputType; pvalue; fdr.
output: outputTablePath: a score per gene whose sign is the direction and whose size is -log10 of the p-value.
next: filter the significant genes ('Filter table'), then functional and promoter analyses.
tips: Needs at least 2-3 samples per group; with one sample per group use 'Fold-Change calculation' and say that no statistics are possible.

== analysis: Fold-Change calculation
summary: Fold change of each gene between experiment and control columns.
use: The size of the change without a statistical test, e.g. one sample per group, or as the ranking column for 'Enrichment analysis'.
input: experimentData/..., controlData/..., type (how replicates are averaged), inputLogarithmBase and outputLogarithmBase (use log2 for the output).
output: outputTablePath with fold-change columns; optionally a histogram.

== analysis: Hypergeometric analysis
summary: Find up- and down-regulated genes by comparing each expression profile with a boundary value using permutations.
use: A robust alternative to the t-test for microarray data with few replicates.
input: experimentData/..., controlData/..., bv, pvalue, fdr.
output: outputTablePath with a signed score per gene.

== analysis: Meta analysis
summary: Combine the up/down results of several independent experiments into one list of consistently regulated genes.
use: The same question was measured in several datasets and the user wants the genes that agree across them.
input: tablePaths, the results of 'Hypergeometric analysis' for each dataset.

== analysis: Differential expression with DESeq
summary: Differential expression between two groups of RNA-seq count columns with DESeq or DESeq2.
use: The input is a table of raw read counts per gene (integers), not normalized expression values.
input: experimentGroup/tablePath + columns, controlGroup/tablePath + columns, deseqVersion.
output: testsTable with fold change and adjusted p-value per gene.
tips: Counts must be raw: normalized or log values give wrong results. Needs replicates in each group.

== analysis: Correlation Analysis
summary: Pearson or Spearman correlation between rows or columns of one or two tables, with p-values.
use: Which genes behave alike across samples, or how similar the samples are.

== analysis: Polynomial Regression analysis
summary: Fit a polynomial trend to each gene's values over time points and report the genes with a significant trend.
use: Time series: which genes change over time.

== analysis: K-means clustering
summary: Group genes with similar expression profiles into a chosen number of clusters.
use: Finding co-expressed gene groups across several conditions or time points.
input: experimentData/tablePath + columns, clusterCount.
output: outputTablePath: each gene with its cluster.
next: analyse each cluster as a gene set (functional classification, promoter analysis).
tips: The number of clusters is a guess: try a few values.

== analysis: CRC clustering
summary: Cluster genes by expression profile without fixing the number of clusters (Chinese restaurant clustering).
use: Like K-means when the number of clusters is unknown.
next: 'CR cluster selector' picks the clusters to keep.

== analysis: CR cluster selector
summary: Save chosen clusters of a 'CRC clustering' result as separate gene tables.

# ============================================================================ functional classification

== analysis: Functional classification
summary: Which biological functions, pathways or diseases are over-represented in a gene list (Fisher's exact test against GO, Reactome, HumanCyc and other classifications).
use: The first question about any gene list: what do these genes do? Use it for a set of genes without a ranking (e.g. significantly changed genes); for a ranked list of all genes use 'Enrichment analysis'.
input: sourcePath, a table with Ensembl gene ids as rows (run 'Convert table' first otherwise); species; bioHub, the classification (allowedValues: 'GO (biological process)', 'Reactome pathways', ...; which ones exist depends on the server); pvalueThreshold; minHits.
output: outputTable, one row per category: number of hits, expected hits, p-value and adjusted p-value, and the hit genes.
next: 'Dot plot' or 'TreeMap on Functional classification' for a picture; report the top categories with adjusted p-values and the genes behind them.
tips: Report adjusted p-values, not raw ones. Very broad categories at the top (e.g. 'cellular process') say little: prefer specific ones. A list of fewer than about 10 genes rarely gives significant results. To compare with the user's own gene sets set bioHub to 'Repository folder' and repositoryHubRoot to the folder of gene tables.

== analysis: Enrichment analysis
summary: Gene set enrichment analysis (GSEA): which functions or pathways are concentrated at the top or bottom of a ranked gene list.
use: The user has a value for every measured gene (fold change, score) rather than a cut-off list; GSEA needs no significance threshold and finds coordinated small changes.
input: sourcePath, a table of Ensembl genes; columnName, the numeric column to rank by (describe with params {sourcePath} for its choices); species; bioHub, the classification.
output: outputTable: per category the enrichment score (ES), normalized score (NES), nominal p-value, number of hits and hit genes.
tips: Give it all measured genes, not only the significant ones. The sign of NES tells whether the category sits at the top or the bottom of the ranking. Set onlyOverrepresented false to see both ends.

== analysis: Functional classification by diagrams
summary: Which pathway diagrams of a repository folder are over-represented in a list of proteins or small molecules.
use: Like 'Functional classification' with the user's own or a database's pathway diagrams as categories.

# ============================================================================ tracks

== analysis: Track to gene set
summary: The genes near the sites of one or more tracks, as a gene table with site counts.
use: From peaks or variants to genes: which genes have a ChIP-seq peak or a mutation in or near them.
input: sourcePaths (tracks); species; from and to, how far upstream of the gene start and downstream of its end a site still counts (bp).
output: destPath, a table of Ensembl genes with counts of sites (overall, in exons, introns, ...).
next: functional classification of the genes; network analysis.
tips: The window decides the answer: a few kb around genes finds promoter-proximal targets, larger windows add distal ones and noise. State the window used.

== analysis: Annotate track with genes
summary: Write into each site of a track the genes it falls in or near.

== analysis: Gene set to track
summary: Make a track of promoter or gene regions for the genes of a table (positions relative to the transcription start site).
use: The sequences to search for binding sites, e.g. promoters from -1000 to +100.
input: sourcePath (Ensembl gene table), species, from, to.
output: destPath, a track.

== analysis: Transcript set to track
summary: Make a track of regions around the start of the transcripts of a table.

== analysis: Get transcripts track
summary: Make a track of the transcripts listed in a table of Ensembl transcript ids.

== analysis: Convert table to track
summary: Turn a table with chromosome, start and end columns into a track.
input: inputTable, chromosomeColumn, fromColumn, toColumn, strandColumn (optional), and the genome (sequenceCollectionPath or genomeId).

== analysis: Convert table to VCF track
summary: Turn a table of variants (chromosome, position, reference and alternative allele columns) into a VCF track.

== analysis: Convert track to table
summary: Turn a track into a table: one row per site, site properties as columns.
use: To filter, join or plot site properties with the table tools.

== analysis: Filter one track by another
summary: Keep (Intersect) or remove (Subtract) the sites of a track that overlap the sites of another track.
use: Peaks inside promoters, variants inside peaks, peaks of one experiment absent from another.
input: inputTrack, filterTrack, mode, maxDistance.

== analysis: Filter track by condition
summary: Keep the sites of a track that satisfy a JavaScript condition on position, length, strand or site properties.
input: inputTrack; condition, e.g. 'length > 100' or a test on a property (variables: seq, from, to, length, strand, type, properties).

== analysis: Filter VCF by genotype
summary: Extract the real variant calls of each sample of a VCF track, dropping homozygous-reference and missing calls.
use: A genotyping-array or multi-sample VCF lists every probed position; this keeps what differs from the reference, one track per sample.
input: inputTrack; mode: heterozygote, homozygote or both.
output: outputPath, a folder with a track <sample>_<mode> per sample.

== analysis: Process track with sites
summary: Resize the sites of a track (extend, shrink to centre or summit), merge overlapping sites, drop short ones.
use: Preparing peaks for motif analysis (e.g. shrink to the summit and extend by 50 bp each side) or making fixed windows around variants.
input: sourcePath, sequences, shrinkMode, enlargeStart, enlargeEnd, mergeOverlapping, removeSmallSites.

== analysis: Remove overlapping sites
summary: Make the sites of a track non-overlapping by keeping the longest, shortest, best-scoring or a random one of each overlapping group.

== analysis: Reduce track
summary: Remove duplicate sites (same position and chosen properties) from a track.

== analysis: Cluster track
summary: Merge closely located sites into clusters with a minimal number of sites.
use: Finding regions dense in sites, e.g. clusters of binding sites or variants.

== analysis: Join tracks
summary: Put the sites of several tracks into one track.

== analysis: SNP matching
summary: Turn a table of SNP ids (rs numbers) into a track with their genomic positions and find the genes they lie in or near.
use: The user has a list of SNPs from a GWAS or a paper.
input: sourcePath, a table whose row ids are rs ids; ensembl (the database version, which fixes the genome build); fivePrimeSize and threePrimeSize, the gene flanks.
output: destPath (track), annotatedPath (SNPs with genes), outputGenes (gene table).

== analysis: Track statistics
summary: Quality statistics of a track or FASTQ file: read counts, quality and nucleotide content per position.
use: A first quality check of sequencing reads.

== analysis: Illumina methylation probes to track
summary: Turn a table of Illumina methylation probe ids (cg...) into a track of their genomic positions.

# ============================================================================ NGS

== analysis: Run MACS 1_4_0 on ChiP-Seq || Run MACS 1_3_7 on ChiP-Seq
summary: Call ChIP-seq peaks from aligned reads with MACS (1.4.0 is the newer version; use it).
use: The user has aligned ChIP-seq reads (BAM tracks) and needs the binding regions.
input: trackPath (the ChIP sample), controlPath (input/IgG control, optional but recommended), gsize (effective genome size), pvalue.
output: outputPath, a track of peaks.
next: 'Track to gene set' for target genes; motif analysis of the peaks.

== analysis: ChIP-seq peak profile
summary: Compute the shape profile of ChIP-seq peaks from the aligned reads, for motif discovery that uses peak shape.

== analysis: ChIPMunk || DiChIPMunk
summary: Discover the strongest DNA motif in a set of sequences such as ChIP-seq peaks (ChIPMunk; DiChIPMunk builds a dinucleotide motif).
use: De novo motif discovery: what sequence pattern do these regions share, when no known motif is assumed.
input: inputSequences (a track or sequence collection), startLength and stopLength (motif length range, e.g. 15 down to 8).
output: a weight matrix in outputLibrary.
next: 'Create matrix logo' when available to draw it; 'Create Match model' or 'Create weight matrix model' to search with it.
tips: Use the top few hundred to thousand peaks, shrunk around their summits; long or numerous sequences make it slow.

== analysis: ChIPHorde || DiChIPHorde
summary: Discover several different DNA motifs in a set of sequences, one after another (ChIPHorde; DiChIPHorde for dinucleotide motifs).
use: Like ChIPMunk when more than one motif is expected, e.g. a factor with co-factors.

== analysis: IPS motif discovery
summary: Discover motifs in a sequence set starting from given frequency matrices (IPS method).

== analysis: Preprocess raw reads

== analysis: Read counter

== analysis: Prepare GTF annotation

== analysis: Mutation effect

== analysis: Mutation effect on sites || Mutation effect on sites advanced
summary: Find the transcription factor binding sites that variants create or destroy, with the genes they may regulate (the advanced version adds factor classes, pathway and disease annotation).
use: Regulatory variants: which non-coding mutations change the binding of which transcription factor near which gene.
input: vcfTrack; genome; siteModels, a profile of binding-site models (e.g. a profile under databases/.../Data/profiles); scoreDiff, the minimal score change; targetGeneTSSUpstream/Downstream, the window linking a site to a gene.
output: outputTable (variant, factor, gain or loss, score change, target gene), tracks of gained and lost sites, the important mutations, and a summary per site model.
tips: These are sequence-based predictions: a changed motif score does not prove changed binding. The track must be on the genome chosen in genome.

== analysis: Compare TFBS mutations || Compare TFBS mutations advanced

use: Comparing two variant sets (cases against controls, tumour against normal): which factors' sites are preferentially hit.
input: yesVCFTrack, noVCFTrack, genome, siteModels, pValueCutoff.
output: siteGainsTable and siteLossesTable, one row per factor model.

# ============================================================================ binding sites (generic part)

== analysis: Site search on gene set
summary: Search the promoters of a gene list for transcription factor binding sites and find the motifs over-represented compared with background genes.
use: Which transcription factors may regulate a set of co-expressed genes (promoter analysis).
input: yesSetPath (the genes of interest) and noSetPath (background genes: unchanged or housekeeping genes), both tables of Ensembl genes; species; from and to (promoter window relative to the transcription start, e.g. -1000 and 100); profilePath, a profile of site models.
output: outputPath, a folder with the tracks of predicted sites in both sets and a summary table: per motif its site frequency in Yes and No promoters, their ratio and a p-value.
next: 'Matrices to molecules' / 'Convert site models to proteins' to turn motifs into transcription factor genes; 'Site search report' for a readable report.
tips: The background matters: without a sensible No set the ratios mean little. Predicted sites are sequence matches, not measured binding.

== analysis: Site search on track
summary: Predict transcription factor binding sites in the sequences under a track (or in a sequence collection) with a profile of site models.
use: Scanning peaks, promoters, variant surroundings or the user's own sequences for binding sites.
input: trackPath; dbSelector, the genome of the track (or seqCollectionPath); profilePath.
output: output, a track of predicted sites, each with its site model and score.
next: 'Site search summary' compares the site counts of two such results (study against background).

== analysis: Site search summary

== analysis: Site search result optimization

== analysis: Site search report || Site search report with matrix table

== analysis: Convert site search summary

== analysis: Matrices to molecules || Convert site models to proteins
summary: Turn a table of binding-site models (matrices) into the transcription factors that bind them, as genes or proteins.
use: After a motif enrichment: the motif names are not the answer the user wants, the factors are.
input: sitesCollection (table with site models as rows), siteModelsCollection (the profile used in the search), species, targetType (e.g. 'Genes: Ensembl').
output: outputTable of transcription factors. One motif often maps to several related factors of a family: say so.

== analysis: Create profile from site model table || Create profile from gene table

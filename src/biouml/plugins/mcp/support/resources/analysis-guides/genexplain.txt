# Guides for the analyses and workflows of the geneXplain platform (TRANSFAC, TRANSPATH, HumanPSD, GTRD,
# GeneWays, Genome Enhancer), written for agents that help a user who is not a bioinformatician.
# Format: see McpGuides. This file is specific to geneXplain servers; the generic guides are in biouml.txt.

# ============================================================================ research topics

== topic: gene-list | I have a list of genes: what do they do and what controls them?
summary: From a gene list (e.g. changed genes, a signature from a paper) to functions and pathways, the transcription factors behind it, master regulators and drug targets.
Start: the list must be a table whose row ids are genes. Any id type will do (symbols, Ensembl, Entrez, UniProt, probes): the workflows below convert it themselves; single analyses need Ensembl ids ('Convert table'). Ask for the species if the table does not say.

1. What do the genes do? Workflow 'Mapping to ontologies (Gene table)' (Common): GO biological process, cellular component, molecular function, Reactome, HumanCyc and transcription factor classes in one run. With a HumanPSD or TRANSPATH licence the workflows of the same name in the HumanPSD and TRANSPATH folders add diseases and signalling pathways. One classification only: 'Mapping to ontology - select a classification (Gene table)', or the analysis 'Functional classification'. Report the top categories by adjusted p-value with their genes.
2. Which transcription factors control them? Workflow 'Identify enriched motifs in promoters (TRANSFAC(R))' (or the GTRD one without a TRANSFAC licence): it searches the promoters of the genes for binding motifs enriched against a background of housekeeping genes and returns the motifs and the factors that bind them. See topic promoter-analysis.
3. What is upstream of all this? Workflow 'Find master regulators in networks (TRANSPATH(R))' (GeneWays variant without a TRANSPATH licence) finds the signalling molecules that reach many of the genes' products. The combined, usually preferred route is 'Upstream analysis (TRANSFAC(R) and TRANSPATH(R))': enriched transcription factors first, then the master regulators above them. See topic master-regulators.
4. Shown as a picture: the workflows above save a network diagram of the top master regulator; biouml_diagram_image draws it; 'Add expression values' colours it by the user's data.
One-call overview: workflow 'Explain my genes' (Common) does a compact version of step 3.
With a ranked list of all measured genes (not a cut-off list) use 'Gene set enrichment analysis (Gene table)' instead of step 1.
Lists of fewer than about 20 genes give weak statistics in steps 1 and 2; more than about 3000 dilute the signal: say so and offer to tighten or loosen the cutoff.

== topic: expression-table | I have an expression table: which genes differ between my groups?
summary: Differential expression from a table of normalized values or raw counts, quality checks, and the gene lists to carry on with.
Look at the table first (biouml_analysis_get_result): which columns are samples, which group each belongs to, whether values are raw counts (integers), log2 values, or linear intensities. Ask the user for the groups if the column names do not tell.

Quality check before statistics: 'PCA' (samples of a group should lie together; an outlier or a batch effect shows here), 'Normalization quality plots' (the value distributions of the samples should look alike), 'Heatmap' of the most variable genes ('Variance filter' first).

Differential expression:
- Two or more groups, replicates in each: analysis 'Limma' (groups given as lists of sample columns; inputLogarithmBase says what the values are) or workflow 'Compute differentially expressed genes using Limma', which also converts ids and splits up- and down-regulated genes.
- Design described by a sample annotation table (several factors, batches, paired samples), or raw RNA-seq counts: 'Guided linear model analysis' (inputType 'Raw counts' applies voom) or workflow 'Estimate DEGs with guided linear model analysis'.
- Raw counts, two groups: also 'Differential expression with DESeq'.
- No replicates: only 'Fold-Change calculation' is possible; say plainly that there is no statistical test.
Result columns of Limma-style tables: logFC (log2 fold change; positive = higher in the first group), P.Value, adj.P.Val (use this one), AveExpr.

Then make the gene lists: 'Filter table', commonly adj.P.Val < 0.05 and logFC > 1 (up) or < -1 (down); state the cutoffs and the counts. Draw a 'Volcano plot'. Continue with topic gene-list for the up and down lists separately, and use 'Enrichment analysis' on the whole table ranked by logFC.

== topic: microarray-raw | I have raw microarray files (Affymetrix CEL, Agilent, Illumina)
summary: Import, normalize and compare raw microarray files.
Import the files into the project (a ZIP of them with the matching format: 'Affymetrix CEL file (*.cel)', 'Agilent microarray file (*.txt)', 'Illumina microarray file (*.txt)'). Normalize experiment and control together: 'Normalize Affymetrix experiment and control' (RMA is a good default method), 'Normalize Agilent experiment and control', 'Normalize Illumina experiment and control'; they give one normalized table per group with probe ids as rows. Then workflow 'Compute differentially expressed genes (Affymetrix probes)' (or the Agilent / Illumina one): it computes fold changes and up/down statistics, converts probes to Ensembl genes, annotates and returns up-regulated, down-regulated and unchanged gene tables. Continue with topic gene-list. More than two groups: normalize all files in one go ('Affymetrix normalization' etc.) and use topic expression-table.

== topic: rna-seq-raw | I have RNA-seq reads (FASTQ) or alignments (BAM)
summary: From FASTQ or BAM files to gene counts and differentially expressed genes with the ready-made RNA-seq workflows.
These workflows run external tools (HISAT2 or Subread for alignment, featureCounts or htseq-count for counting, limma-voom for statistics) and take from tens of minutes to many hours: start, then poll biouml_task with growing intervals.
- FASTQ, experiment against control, human: 'Full RNAseq analysis with HISAT2, featureCounts and limma (single-end)' or '(paired-end)' — alignment, counts and differential expression in one run. The Subread and htseq-count variants do the same with other tools; there is no reason to prefer them unless the user asks.
- FASTQ to counts only: 'RNAseq analysis with HISAT2 (single-end)' / '(paired-end)'.
- BAM files: 'From multiple BAM files to gene counts', or 'Analyze multiple BAM files to detect DEGs' for experiment against control.
- Reads in SRA format: 'SRA to FASTQ' first.
- Variants from RNA-seq or genome sequencing: 'Find genome variants and indels from RNA-seq_hg38 (single-end)', 'Find genome variants and indels from full-genome NGS_hg38' (hg19 variants exist too).
Ask whether reads are single- or paired-end and which genome build is wanted. A count table from elsewhere: go to topic expression-table. Quality of the reads: 'Track statistics'; cleaning: 'Preprocess raw reads'.

== topic: promoter-analysis | Which transcription factors regulate my genes?
summary: Enriched binding motifs and motif combinations (composite modules) in the promoters of a gene set; choice of background, profile and promoter window.
Idea: genes that change together often share binding sites of the same transcription factors in their promoters. The analysis counts predicted sites of each known motif in the promoters of the study genes (Yes set) and of background genes (No set) and reports the motifs that are more frequent in the Yes set.

Shortest way: workflow 'Identify enriched motifs in promoters (TRANSFAC(R))' — input the gene table; defaults: promoters from -1000 to +100 around the transcription start, background 'data/Public/Data sets/Data/Housekeeping genes (<species>) 300', the non-redundant vertebrate TRANSFAC profile. It returns the enriched motifs with their statistics, the transcription factors (as Ensembl genes) that bind them, and a profile of the enriched motifs. 'Identify enriched motifs in promoters (GTRD)' does the same with the freely available GTRD motif collection.
Better background when available: genes measured in the same experiment that did not change (the 'unchanged' table of a differential expression workflow), of similar number or more than the Yes set.
The analysis behind it: 'Search for enriched TFBSs (genes)'; output columns: adjusted fold enrichment of sites (Adj. site FE) and of sequences with sites, and their FDRs — report motifs with FE clearly above 1 and FDR below 0.05.

Combinations of factors: transcription factors act in groups. 'Identify enriched composite modules in promoters (TRANSFAC(R))' (or GTRD) adds a search (genetic algorithm, slower) for the combination of motifs that best separates the Yes from the No promoters — the composite module — and the factors in it.
Tissue or cell specific promoters (CAGE-based start sites): 'Identify enriched motifs in tissue specific promoters (TRANSFAC(R))' / 'cell specific'.
Another species with poor annotation: 'Cross-species identification of enriched motifs in promoters, using orthologue information (TRANSFAC(R))'.
Regions rather than genes (peaks, enhancers): topic chip-seq. The user's own DNA sequence: 'Analyze any DNA sequence (TRANSFAC(R))' or '(GTRD)'.

Tell the user: these are predictions from sequence; a motif usually stands for a family of related factors; the natural next question — what activates these factors — is topic master-regulators.

== topic: master-regulators | What is the upstream cause? Master regulators and drug targets in signalling networks
summary: Upstream analysis: from genes to their transcription factors and on to the master regulators in the signalling network; effectors downstream; drug target ideas.
Idea (upstream analysis): changed genes are the end of a signalling cascade. Step 1 finds the transcription factors that explain the expression change (topic promoter-analysis); step 2 searches the signalling network (TRANSPATH, or the free GeneWays network) upstream of these factors for molecules — receptors, kinases, adaptors — from which the signal can reach many of them within a few reaction steps. Such master regulators are candidate causes of the observed state and candidate intervention points.

- Both steps in one run: workflow 'Upstream analysis (TRANSFAC(R) and TRANSPATH(R))' (input: gene table; background: housekeeping genes by default). 'Enriched upstream analysis (TRANSFAC(R) and TRANSPATH(R))' uses the stricter enrichment-based motif search of 'Identify enriched motifs in promoters' for step 1 and is the better default. Without a TRANSPATH licence: 'Upstream analysis (TRANSFAC(R) and GeneWays)'.
- Step 2 alone, starting from any gene or protein list (e.g. transcription factors already known, or the changed genes themselves): 'Find master regulators in networks (TRANSPATH(R))' or '(GeneWays)'. Variants: 'TF only' restricts regulators to transcription factors; 'with context genes' favours regulators consistent with a second gene list (e.g. all expressed genes); 'and weighting' uses a numeric column (e.g. fold change) as weights; 'Find 10 master regulators' searches further upstream (up to 10 steps). Several gene lists at once: 'Find master regulators for multiple gene sets'.
- The other direction — what do my molecules act on (downstream)? 'Find common effectors in networks (TRANSPATH(R))' / '(GeneWays)'.
- With feedback: 'Upstream analysis with feedback loop' keeps master regulators whose own gene is changed in the data; 'Search for self-regulating transcription factors'.
The analyses behind the workflows: 'Regulator search' (upstream), 'Effector search' (downstream), then 'Visualize results' (network diagram of a chosen regulator), 'Save hits', 'Save network'.

Reading the result table: one row per candidate regulator; Score (higher is better: reaches more input molecules in fewer steps), FDR and Z-score (specificity against random inputs; keep FDR below 0.05), 'Reached from set' / hits (how many input molecules it reaches) and the radius. Report the top regulators with their gene symbols and what they are (receptor, kinase, ...), and draw the network of the best one (the workflows save it; biouml_diagram_image). Colour it with 'Add expression values'.
Drug targets and drugs for the regulators found: topic drug-targets.
Caveats to state: the network is literature knowledge, not specific to the user's tissue; a master regulator is a hypothesis to test, strongest when it is itself changed in the data or known in the disease.

== topic: chip-seq | I have ChIP-seq (or ATAC-seq) peaks: target genes, motifs, co-factors
summary: From a peak track to target genes and their functions, the motifs in the peaks, and motif combinations; peak calling from alignments.
Input: a track of peaks (import BED with the right genome build). From aligned reads call peaks first: 'Run MACS 1_4_0 on ChiP-Seq'.
- Target genes and what they do: workflow 'ChIP-Seq - Identify and classify target genes' (Common; HumanPSD and TRANSPATH variants add diseases and pathways): genes near the peaks ('Track to gene set'), functional classification, and a network cluster of the targets.
- Which factors bind in the peaks: 'ChIP-Seq - Identify TF binding sites on peaks (TRANSFAC(R))' (known motifs enriched in the peaks against background regions), or 'Identify enriched motifs in tracks (TRANSFAC(R))', which builds a random genomic background itself and adds a MEALR model of motif combinations. The top motif should be the immunoprecipitated factor; the others are candidate co-factors.
- Combinations: 'ChIP-Seq - Identify composite modules on peaks (TRANSFAC(R))'.
- A new motif not in the databases: 'ChIPMunk' (one motif) or 'ChIPHorde' (several) on the top peaks shrunk around their summits ('Process track with sites').
- Several peak sets: 'ChIP-Seq - Identify TF binding sites on peaks for multiple datasets (TRANSFAC(R))'; overlaps with 'Filter one track by another' or 'Intersect tracks'.
For motif analysis use narrow regions (about 100-300 bp around summits) and, for very large peak sets, the strongest few thousand peaks.

== topic: variants | I have variants (VCF, SNP list): which matter and how?
summary: Regulatory and coding effects of variants, the genes and pathways affected, variants in binding sites, and the route to personalized drug targets.
- A list of SNP ids (rs numbers): workflow 'Analyze SNP list (TRANSFAC(R))_hg38' (or _hg19; GTRD variant without a TRANSFAC licence): positions and nearby genes, binding sites created or destroyed by each SNP, protein effect prediction (SIFT). The 'TRANSFAC(R) and TRANSPATH(R)' variant adds pathways of the affected genes. Single steps: 'SNP matching', 'Mutation effect on sites'.
- A VCF track (hg38): workflow 'Discover regulatory mutations using GTRD and TRANSFAC' — keeps the variants inside experimentally bound regulatory regions (GTRD ChIP-seq) and reports the binding sites they change, with the factors and target genes. Analyses: 'Mutation effect on sites advanced', 'Split VCF by regulation'.
- Which factors' sites are hit more often than expected: 'Find enriched TF binding sites in variation sites (TRANSFAC(R))'; two variant sets against each other: 'Compare TFBS mutations'.
- Coding effects: 'Mutation effect'. From variants to a weighted gene list: 'Mutations to genes with weights', then topic gene-list.
- Master regulators of a network disturbed by a patient's variants: 'Find master regulators in mutated network (TRANSPATH(R))'.
- A patient's variants to drug targets and a report: the Genome Enhancer perspective (biouml_perspective_select 'Genome Enhancer' returns its step-by-step guide).
Before anything: check the genome build of the track (biouml_bsa_track_genome) and pick the matching workflow; a genotyping-array VCF needs 'Filter VCF by genotype' first. Binding-site effects are sequence-based predictions.

== topic: drug-targets | Which drug targets and drugs fit my data?
summary: Genome Enhancer for the full route from omics data to drug targets and drugs; single analyses for druggable targets among a gene list.
The full, recommended route is Genome Enhancer: from expression, genomics, proteomics, epigenomics or metabolomics data to transcription factors, master regulators, drug targets and candidate drugs with a report. Select the perspective (biouml_perspective_select 'Genome Enhancer') and follow its guide; its core analysis is 'Generate workflow from annotation diagram'.
Shorter, for a gene list that already holds candidate targets (e.g. master regulators from topic master-regulators, with a score column): 'PSD pharmaceutical compounds analysis' finds known drugs (HumanPSD) acting on them, optionally restricted to chosen diseases; 'Pharmaceutical Compounds analysis' adds compounds predicted by the cheminformatics tool PASS with toxicity and effect filters. Both return a table of compounds and a table of targets with druggability scores.
Always say that the drugs are computational suggestions for a specialist to consider, not treatment advice.

== topic: mirna | microRNAs: targets, regulators, feed-forward loops
summary: miRNAs that may target a gene list, target genes of miRNAs, and transcription factors controlling miRNAs.
- Which miRNAs may regulate my genes: 'Analyze miRNA target enrichment' (miRNAs whose predicted targets are enriched in the gene list), or workflow 'Prediction of miRNA binding sites' (binding sites in the 3' UTRs of the genes).
- Targets of my miRNAs: 'Get miRNA targets' (TargetScan), then topic gene-list on the targets.
- Which transcription factors control my miRNAs: 'Identify enriched motifs in tissue specific miRNA promoters (TRANSFAC(R))' / 'cell line specific'.
- Loops of a transcription factor, a miRNA and a common target gene: 'miRNA feed forward loops'.
miRNA tables use miRBase ids as row ids.

== topic: explore-samples | Look at my samples: quality, clusters, classifiers
summary: PCA, heatmaps, t-SNE, clustering of genes and samples, and random forest classifiers on a data table.
- Do the samples group as expected: 'PCA' (groups given as column lists), 't-SNE' for many samples, 'Heatmap' (hierarchical clustering of rows and columns; at most 5000 rows — reduce with 'Variance filter' first), 'Correlation Analysis' between samples.
- Value distributions per sample: 'Normalization quality plots'.
- Groups of genes with similar profiles: 'K-means clustering', 'CRC clustering'; analyse each cluster as a gene list.
- Predict a class or a value from the data: 'Train random forest' (reports accuracy and the most important variables), then 'Random forest prediction' on new samples.
Tables for PCA, heatmaps and clustering should be on a log scale ('Transform table').

# ============================================================================ normalization and expression statistics

== analysis: Affymetrix CEL file (*.cel) || Agilent microarray file (*.txt) || Illumina microarray file (*.txt)
summary: Import formats for raw microarray files (Affymetrix CEL, Agilent, Illumina); the files must be normalized after import.
use: See topic microarray-raw. Import a ZIP of the files with the matching format.

== analysis: Normalize Affymetrix experiment and control || Normalize Agilent experiment and control || Normalize Illumina experiment and control
summary: Normalize raw microarray files of an experiment group and a control group together, giving one normalized table per group.
use: The start of a two-group microarray comparison; the outputs are the inputs of the 'Compute differentially expressed genes (... probes)' workflows.
input: the raw files of each group (celFiles / agilentFiles / illuminaFiles and controlFiles); for Affymetrix a method (RMA is a good default; arrays of the newer designs are always RMA).
output: outputPath (experiment) and controlOutputPath (control), tables with probe ids as rows and one column per file.
tips: Keep outputLogarithmBase at log2. Needs R on the server.

== analysis: Affymetrix normalization || Agilent normalization
summary: Normalize a set of raw microarray files into one table of expression values (probes as rows, files as columns).
use: All samples of an experiment in one table, e.g. for more than two groups; then topic expression-table.
param dualChannel: true for two-colour arrays (Cy5/Cy3 on one slide; the result is a log ratio of the channels), false for one-colour arrays.

== analysis: Normalization quality plots
summary: Box plots and density plots of the value distributions of the sample columns of a table.
use: Checking that samples are comparable before statistics: after normalization the distributions should look alike.

== analysis: Limma
summary: Differentially expressed genes between up to five groups of samples with linear models (limma): log fold change, p-value and adjusted p-value per gene.
use: The standard differential expression test on a table of normalized expression values (microarray or normalized RNA-seq) when each group has replicates.
input: inputTablePath; inputLogarithmBase (what the values are); for each group a name and its sample columns: firstName/firstColumns, secondName/secondColumns, ...
output: outputFolderPath with one table per pair of groups: logFC, AveExpr, t, P.Value, adj.P.Val, B.
next: 'Filter table' on adj.P.Val and logFC for the up and down gene lists; 'Volcano plot'; topic gene-list.
tips: Column names must start with a letter and contain only letters, digits and _. logFC is first group minus second. For raw counts or a design with batches or pairs use 'Guided linear model analysis'.

== analysis: Guided linear model analysis
summary: Differential expression with limma for designs described by a sample annotation table: several factors, batches, pairing, raw RNA-seq counts (voom).
use: RNA-seq count tables, and any experiment with more structure than a few plain groups.
input: inputTablePath (features x samples); inputType ('Raw counts', 'Transformed counts' or 'Normalized expression'); sampleTablePath, a table with one row per sample, sampleColumn (the column with the sample names as in the data table), mainFactor (the column defining the groups), refLevel (the control level), controlFactors (batch, patient, ...).
output: outputFolderPath: a table per comparison of main-factor levels (logFC, P.Value, adj.P.Val) and an ANOVA table.
tips: The sample table usually has to be made first (biouml_repo_new_element kind table): ask the user which sample belongs to which group. Choices of mainFactor appear after sampleTablePath is bound.

== analysis: EBarrays
summary: Differential expression between up to five groups with the empirical Bayes mixture model of EBarrays: posterior probabilities of expression patterns.
use: An alternative to limma for few replicates; usually limma is the first choice.

== analysis: Calculate M-values
summary: Convert methylation beta-values in chosen columns to M-values, which suit statistical tests.
use: Before differential methylation statistics on beta-value tables.
param columnGroup: The columns with methylation beta-values (0-1) to convert: tablePath and columns.

== analysis: Variance filter
summary: Keep the rows of a table with the highest (or lowest) variance across chosen columns.
use: Reducing a table to its most variable genes before 'Heatmap', 'PCA' or clustering.
param dataColumns: The numeric sample columns over which the variance of each row is computed.

== analysis: Heatmap
summary: Heatmap of a numeric table with hierarchical clustering of rows and columns.
use: Showing expression patterns of a gene set across samples.
input: inputTablePath (at most 5000 rows), scale (Row is usual for expression), transform, optional sample groups.
output: outputFolderPath with the image and the ordered row and column ids.

== analysis: PCA
summary: Principal component analysis of the samples of a table: a scatter plot of the first two components, coordinates and explained variance.
use: The first quality check of an expression dataset: do replicates group together, are there outliers or batch effects.
input: inputTablePath; groups as firstName/firstColumns, secondName/secondColumns, ...

== analysis: t-SNE
summary: t-SNE map of the data points of a table, coloured by a group column.
use: Visualizing many samples or cells; for a handful of samples PCA is the right tool.
tips: Perplexity must be smaller than a third of the number of points.
param maxIter: Number of optimization steps; 1000 is usually enough, more only if the map still changes.
param pcaCenter: true (usual): centre each variable before the initial PCA.
param pcaScale: true: also scale each variable to unit variance before the initial PCA, so that variables on different scales count equally; false for expression values on one scale.
param eta: Learning rate of the optimization; 200 is the standard. Lower it (10-100) if the points form a ball, raise it for very large data.

== analysis: Train random forest
summary: Train a random forest to predict a class or a value from the columns of a table; reports accuracy and variable importance.
use: Building a classifier (e.g. responders against non-responders) or finding the most informative variables.
input: columnTablePath (samples as rows, variables as columns), responseColumn, predictorColumns.
output: outputFolderPath with the model, its error estimates and the importance table.
param seed: Start value of the random number generator; keep it to make the result reproducible, change it to see how stable the result is.

== analysis: Random forest prediction
summary: Apply a trained random forest model to new data.
input: inputTablePath with the same predictor columns as in training; randomForestPath, the model from 'Train random forest'.

== analysis: GlycanR
summary: Glycan data analysis with the glycanr R package: plots and outlier detection per group.

== analysis: LRPath
summary: Gene set enrichment by logistic regression (LRPath): categories whose genes tend to have more significant p-values.
use: An alternative to GSEA when the ranking is a p-value column of a differential expression table.
input: inputTablePath (Ensembl genes), predictorColumn (e.g. the p-value), bioHub (the classification), significanceColumn and significanceCut.

== analysis: Compare analysis results
summary: Compare the p-values of two result tables (e.g. two enrichment analyses) and find the entries that differ significantly.
use: What is enriched in one gene set and not in the other: GO terms or motifs specific to up- against down-regulated genes.
input: firstTablePath/firstColumn and secondTablePath/secondColumn, the p-value columns of two results of the same kind.
output: a scatter plot and a table of differences with FDR.

== analysis: Fast table filter
summary: Filter a large table with an SQL-like condition.
use: Like 'Filter table' for tables too large to filter row by row; the condition is SQL ('ColumnA > 5 AND ColumnB < 0.05').

== analysis: Replace outliers
summary: Clip the values of chosen columns to a lower and an upper bound.

== analysis: Intersect tables
summary: The rows whose ids are in both tables.
use: The genes common to two lists. For the overlap picture and all subsets use 'Venn diagrams'.
param leftGroup: The first table and the columns to take from it: tablePath and columns.
param rightGroup: The second table and the columns to take from it: tablePath and columns.

== analysis: Verify Condition for Table
summary: Workflow helper: pass a table on only if it meets a condition (enough rows, a column present, ...).
use: Not a research step; used inside workflows.
param inputPath: The table to check.
param conditionMode: The rule to check: the table has more rows than conditionValue; a column of that name is present; a JavaScript expression holds; the table has a property of that name.
param conditionValue: The value the rule is checked against: a row count, a column name, an expression or a property name.
param outputPath: Where the table is copied to when the condition holds.
param emptyOutput: true: when the condition fails, write an empty table instead of failing, so that later workflow steps can go on.

== analysis: Import from BC Platform || Import from TranSMART
summary: Load a dataset from a BC|Platform or tranSMART server into a table; needs that server's address and credentials from the user.
param apiKey: The user's API key for the BC|Platform server. Ask the user for it; never invent one, and do not repeat it in answers.
param password: The user's password for the server. Ask the user; do not repeat it in answers.
param dataSet: The name of the data set on the server to load.
param genes: Gene symbols to restrict the query to, comma-separated; empty for no restriction.
param geneIds: As genes, by id.
param geneSignatures: Names of gene signatures stored on the server to restrict the query to.
param geneSignatureIds: As geneSignatures, by id.
param proteins: Protein names to restrict the query to.
param proteinIds: As proteins, by id.
param pathways: Pathway names to restrict the query to (their genes are used).
param pathwayIds: As pathways, by id.
param snps: SNP ids (rs numbers) to restrict the query to.

# ============================================================================ promoters and tracks

== analysis: Create tissue-specific promoter track
summary: Make a track of promoters of a gene list using the transcription start sites active in a chosen tissue or cell type (FANTOM5 CAGE data).
use: Promoter analysis in a specific tissue: genes often use different start sites in different tissues.
input: inputSetPath (genes), cageDatabase, cellCondition (a tissue or cell from allowedValues; use filter to find it), from and to.
output: outputPath, a track for 'Site search on track' or the enrichment analyses for tracks.

== analysis: Create transcript region track
summary: Make a track of a chosen region of transcripts: 3' UTR, 5' UTR, promoter, an exon or an intron.
use: Sequences for miRNA binding site or regulatory element searches in UTRs.

== analysis: Create random track
summary: Make a track of random genomic regions matching the number and lengths of the regions of a study track.
use: The background (No set) for motif enrichment in peaks or other regions when no natural control exists.
input: inputTrackPath, dbSelector (genome), seqNumber; optionally fixed length or positions relative to transcription starts.

== analysis: Intersect tracks
summary: Split the intervals of a track into those that overlap a filter track and those that do not, with a coverage threshold.
use: Peaks shared between two experiments and peaks unique to one; regions inside or outside annotated features.

== analysis: Find regulatory regions
summary: Make a track of the regulatory regions of a gene list: promoter windows, placed on ChIP-seq peaks near the gene when a peak track is given.
use: Better regions than fixed promoters for site search when binding or open-chromatin data exist. A Genome Enhancer step.
param inputGenes: The table of genes (Ensembl ids) whose regulatory regions are wanted.
param chipSeqPeaks: Optional track of ChIP-seq or open-chromatin peaks: regions are then placed on the peaks near each gene instead of on its promoter only.
param geneLeftBoundShift: How far upstream of the gene's start, in base pairs (negative), peaks or mutations are still assigned to the gene. -2000 keeps to the vicinity; -50000 takes in distal enhancers.
param geneRightBoundShift: How far downstream of the gene's end, in base pairs, peaks or mutations are still assigned to the gene.
param regulatoryRegionFrom: Start of the region made around each peak summit (or mutation cluster), in base pairs relative to it; -200 with regulatoryRegionTo 200 gives 400 bp regions, a good size for motif search.
param regulatoryRegionTo: End of the region made around each peak summit (or mutation cluster), in base pairs relative to it.

== analysis: Find regulatory regions with mutations
summary: Make a track of regulatory regions of a gene list, placed where the mutations of a variant track are densest around each gene.
use: Promoter analysis centred on a patient's regulatory variants. A Genome Enhancer step.
param inputGenes: The table of genes (Ensembl ids) whose regulatory regions are wanted.
param geneLeftBoundShift: How far upstream of the gene's start, in base pairs (negative), peaks or mutations are still assigned to the gene. -2000 keeps to the vicinity; -50000 takes in distal enhancers.
param geneRightBoundShift: How far downstream of the gene's end, in base pairs, peaks or mutations are still assigned to the gene.
param regulatoryRegionFrom: Start of the region made around each peak summit (or mutation cluster), in base pairs relative to it; -200 with regulatoryRegionTo 200 gives 400 bp regions, a good size for motif search.
param regulatoryRegionTo: End of the region made around each peak summit (or mutation cluster), in base pairs relative to it.

== analysis: Split VCF by regulation
summary: Split a VCF track into the variants inside regulatory regions (a regulation track) and the others.
use: Preparing Yes and No variant sets for 'Compare TFBS mutations'.
param inputVCF: The VCF track with the variants to split.
param regulationTrack: A track of regulatory regions (e.g. GTRD ChIP-seq peaks or promoters): variants inside them go to outYes, the others to outNo.
param defaultVCF: A VCF track of background variants: when fewer than minNoSize variants fall outside regulatory regions, random variants from it fill the No set up.

== parameters: geneXplain
param promoterFrom: Start of the promoter window relative to the transcription start site, in base pairs; negative is upstream. -1000 is the usual value; -500 focuses on the core promoter, -5000 or more also takes in distal elements and adds noise.
param promoterTo: End of the promoter window relative to the transcription start site, in base pairs; positive is downstream. 100 is the usual value.
param cellCondition: The tissue or cell type whose active transcription start sites (FANTOM5 CAGE data) define the promoters. Leave it at the default / 'Nothing selected' entry to use the annotated gene starts; use biouml_analysis_describe with filter (e.g. 'liver') to find an entry among the hundreds.
param geneticParameters: Settings of the genetic algorithm that searches for the best motif combination.
param iterationsCount: How many generations the genetic algorithm runs. More gives a better module and takes proportionally longer; 300 is a full run, 50-100 a quick look.
param populationSize: How many candidate modules are kept in each generation. Larger explores more combinations and takes longer; 1000 is a full run, 200 a quick look.
param modelParameters: The shape of the composite module searched for: how many motifs it may hold, how many sites of each count, and the window they must fit into. The defaults suit promoters.
param gaussModelParameters: Settings of one module of the model: the number of motifs in it, the number of best sites counted per motif, and the width of the window in which the sites are scored together.
param multiGaussModelParameters: The composite module model itself (see modelParameters of 'Construct composite modules').
param decorators: Changes applied to the signalling network before the master regulator search, e.g. weights from the user's data; leave empty unless a workflow sets it.
param initialTrackPath: Read-only, internal.
param yesTrackPath: The track of the regions of interest (Yes set): e.g. promoters of the changed genes, or peaks.
param noTrackPath: The track of background regions (No set) to compare against: e.g. promoters of unchanged genes, or random regions of similar length.
param numTopRanking: How many of the best-ranked molecules (rows of the search result, ordered by rankColumn) are used. 1 gives the network of the top master regulator; 3-5 gives a wider picture.
param topSelected: How many of the best-ranked master regulators are put into the diagram; about 10 stays readable.
param geneIdColumn: The column that holds the Ensembl gene ids of each row (a row may list several); '(none)' until the table is set.
param resultDiagramPath: Where the network diagram is written; draw it with biouml_diagram_image.
param structTablePath: Where the table of compounds (drugs) is written: one row per compound with its score, targets and clinical status.
param targTablePath: Where the table of targets is written: one row per target gene with its druggability score and the compounds acting on it.
param controlFiles: The raw files of the control samples, as a list of repository paths; they are normalized together with the experiment files.
param bgCorrection: Background correction: RMA is the standard; MAS reproduces the Affymetrix MAS5 pipeline; None skips it.
param normMethod: How arrays are made comparable: 'quantiles' is the RMA standard; 'constant' scales to a common mean as MAS5 does; the others are rarely needed.
param pmCorrection: 'pmonly' uses perfect-match probes only (RMA standard); 'subtractmm' subtracts mismatch probe signal (MAS5 style).
param summarization: How the probes of a probe set are combined into one value: 'medianpolish' is the RMA standard, 'mas' the MAS5 one.
param tScoreColumn: The column with the transcriptomics score of each gene (e.g. log fold change); '(none)' when there is no such data.
param pScoreColumn: The column with the proteomics score of each gene; '(none)' when there is no such data.
param diseases: The diseases the analysis is focused on: targets and drugs known for them are ranked higher. Names must be taken from allowedValues; find them with biouml_analysis_describe and filter (e.g. 'carcinoma'). Leave empty for no disease focus.
param targetScanDB: The TargetScan table of predicted miRNA target sites; keep the default.
param expertSettings: Fine-tuning for unusual data; the defaults suit most datasets, so change a value only for a stated reason.
param lowerLogValue: Lower limit for log2 expression values: smaller values are treated as outliers and raised to it. -20 leaves real data unchanged.
param upperLogValue: Does two things. A table whose values are all positive and not above this limit is taken to be log2-scale already and is not log-transformed; anything else is taken as linear. Log2 values above it are treated as outliers and lowered to it. 20 suits intensities and counts; lower it only if linear data never exceed 20 and are wrongly taken as log-scale.
param lowerLogValueProt: As lowerLogValue, for proteomics tables.
param upperLogValueProt: As upperLogValue, for proteomics tables.
param geneBoundShiftLeft: How far upstream of a gene's start, in base pairs (negative), variants and peaks are still assigned to that gene. -5000 is the usual value; -50000 also takes in distal enhancers.
param geneBoundShiftRight: How far downstream of a gene's end, in base pairs, variants and peaks are still assigned to that gene. 5000 is the usual value.
param topGenes: How many of the most up-regulated genes are analysed for shared regulators. 300 is the usual value; 100-200 for a sharper signal with strong data, up to about 1000 when changes are small.
param bottomGenes: How many of the most down-regulated genes are analysed for shared regulators; see topGenes.
param middleGenes: How many unchanged genes (around the median of the ranking) form the background that promoters of changed genes are compared with. 500 is the usual value; keep it at least as large as topGenes.
param useFeedbackLoops: true: master regulators whose own genes are regulated by the transcription factors found (a positive feedback loop) are ranked higher, and the loops are shown in the result diagram; false: feedback is not taken into account.
param checkMode: true: check before starting that every chosen condition has usable data, and stop with a message if not; a cheap safeguard for a run that takes hours.
